## ✅ VERIFICATION: Security Features

### 1. **AES Encryption** ✅
- **Algorithm**: AES-256-CBC (Advanced Encryption Standard)
- **Key Size**: 256-bit (32 bytes)
- **Mode**: CBC (Cipher Block Chaining)
- **Implementation**: Payload encryption for transaction data

### 2. **HMAC Authentication** ✅
- **Algorithm**: HMAC-SHA256
- **Key**: K1 (derived from NID + Activation Code + MAC + Password)
- **Purpose**: Message integrity verification and authenticity
- **Verification**: Timing-safe comparison to prevent timing attacks

### 3. **Biometric/Password** ✅
- **Current Implementation**: Password (12334 or user-defined)
- **Role**: K2 - Encryption key material + User authentication
- **Production**: Replace password with biometric (fingerprint, face ID)
- **Requirements**: Minimum 4 characters

### 4. **Timestamp** ✅
- **Format**: ISO 8601 UTC (e.g., "2026-04-25T14:30:45.123456")
- **Purpose**: 
  - Key derivation with password
  - Replay attack prevention
  - Transaction chronological ordering
- **Verification**: Each transaction timestamp must be newer than previous

## 🔐 ENCRYPTION FRAMEWORK

### **Multi-Layer Security Model**

```
┌─────────────────────────────────────────────────────────────────┐
│                    TRANSACTION FLOW                             │
└─────────────────────────────────────────────────────────────────┘

LAYER 1: USER AUTHENTICATION (Login/Registration)
├─ Username + Password verified
├─ K1 generated: HMAC(NID + ActivationCode + MAC + Password)
├─ K2 stored: SHA256(Password)
└─ Session token issued

LAYER 2: TRANSACTION PREPARATION (Client-side)
├─ Message created: {sender, receiver, amount, timestamp}
├─ HMAC-F1 generated: HMAC(K1, Message)
├─ Payload created: {message, hmac}
└─ Ready for encryption

LAYER 3: ENCRYPTION (Client-side)
├─ Derive key: SHA256(Password + Timestamp)
├─ Generate random IV (16 bytes)
├─ Encrypt payload: AES-256-CBC(Key, Payload)
├─ Combine: IV + Ciphertext
└─ Encode: Base64

LAYER 4: TRANSMISSION (Network)
├─ Send encrypted_payload + hmac_value + timestamp
├─ HTTPS recommended for transport security
└─ Server verifies credentials

LAYER 5: SERVER VERIFICATION
├─ Password verification
├─ Timestamp validation (replay attack check)
├─ Payload decryption: AES-256-CBC(Derived Key, Ciphertext)
├─ HMAC verification: F1 == F2
└─ Transaction execution if all checks pass

LAYER 6: POST-TRANSACTION
├─ Update last transaction timestamp
├─ Record encrypted transaction
├─ Update balances
└─ Return success/failure
```

## 🔑 KEY HIERARCHY & DERIVATION

### **Key Generation Flow**

```
REGISTRATION PHASE:
┌─────────────────────────────────────────────────────────────┐

Input: NID, Username, Password, MAC Address
   ↓
   ├─ Activation Code (generated by bank)
   │
   ├─ K1 GENERATION (HMAC Key for transactions)
   │  └─ K1 = HMAC-SHA256(
   │       key="epayment_master_key",
   │       msg=NID + ActivationCode + MAC + Password
   │     )
   │
   └─ K2 GENERATION (User password storage)
      └─ K2_Hash = SHA256(Password)
         (stored in database for authentication)

Database stores: {username, K1, K2_Hash, NID, MAC}
```

### **Transaction Encryption Key Derivation**

```
TRANSACTION PHASE:
┌─────────────────────────────────────────────────────────────┐

Client provides: Password, Timestamp
   ↓
   └─ Encryption Key = SHA256(Password + Timestamp)
      │
      ├─ This key is temporary (valid only for this transaction)
      ├─ Timestamp ensures key is time-bound
      ├─ Different for each transaction (timestamp changes)
      └─ Only client and server can compute it (they have password)
```

## 🔄 ENCRYPTION/DECRYPTION HIERARCHY

### **CLIENT-SIDE (Encryption Process)**

```
┌────────────────────────────────────────────────────────────────┐
│ STEP 1: PREPARE TRANSACTION MESSAGE                           │
├────────────────────────────────────────────────────────────────┤

Message = {
  "sender": "alice",
  "receiver": "bob",
  "amount": 100.0,
  "timestamp": "2026-04-25T14:30:45.123456"
}

         ↓ (INPUT TO HMAC)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 2: GENERATE HMAC FOR INTEGRITY (F1)                      │
├────────────────────────────────────────────────────────────────┤

Using K1 (from server during prepare)
F1 = HMAC-SHA256(
  key=K1,
  msg=JSON_CANONICAL(Message)
)
Result: Hex string (64 characters)

         ↓ (CREATE PAYLOAD)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 3: CREATE PAYLOAD                                         │
├────────────────────────────────────────────────────────────────┤

Payload = {
  "message": {...},
  "hmac": "F1_VALUE"
}

Payload_JSON = JSON.stringify(Payload)

         ↓ (ENCRYPT WITH PASSWORD + TIMESTAMP)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 4: DERIVE ENCRYPTION KEY                                  │
├────────────────────────────────────────────────────────────────┤

Encryption_Key = SHA256(Password + Timestamp)
                = 256-bit key (32 bytes)

         ↓ (GENERATE IV)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 5: GENERATE RANDOM IV                                     │
├────────────────────────────────────────────────────────────────┤

IV = Random 16 bytes
(Different for each transaction)

         ↓ (ENCRYPT)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 6: AES ENCRYPTION                                         │
├────────────────────────────────────────────────────────────────┤

Ciphertext = AES-256-CBC(
  key=Encryption_Key,
  iv=IV,
  plaintext=Payload_JSON
)

         ↓ (COMBINE & ENCODE)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 7: COMBINE & BASE64 ENCODE                               │
├────────────────────────────────────────────────────────────────┤

Encrypted_Data = IV + Ciphertext
Encoded = Base64(Encrypted_Data)
(16 bytes IV + variable ciphertext, base64 encoded)

         ↓ (SEND TO SERVER)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 8: SEND TO SERVER                                         │
├────────────────────────────────────────────────────────────────┤

POST /api/transaction/send
{
  "receiver_username": "bob",
  "amount": 100.0,
  "password": "user_password",
  "timestamp": "2026-04-25T14:30:45.123456",
  "encrypted_payload": "ENCODED_DATA",
  "hmac_value": "F1_VALUE"
}
```

### **SERVER-SIDE (Decryption & Verification Process)**

```
┌────────────────────────────────────────────────────────────────┐
│ STEP 1: RECEIVE REQUEST                                        │
├────────────────────────────────────────────────────────────────┤

Receive: encrypted_payload, hmac_value, password, timestamp
Get User: From session token (authenticated)

         ↓ (VERIFY PASSWORD)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 2: VERIFY PASSWORD                                        │
├────────────────────────────────────────────────────────────────┤

Received_Hash = SHA256(Password)
Stored_Hash = User.K2_Hash
✓ MUST MATCH - Otherwise: 401 Unauthorized

         ↓ (DERIVE KEY)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 3: DERIVE SAME ENCRYPTION KEY                            │
├────────────────────────────────────────────────────────────────┤

Encryption_Key = SHA256(Password + Timestamp)
(Same as client since we have same password & timestamp)

         ↓ (DECODE BASE64)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 4: DECODE BASE64                                          │
├────────────────────────────────────────────────────────────────┤

Encrypted_Bytes = Base64_Decode(encrypted_payload)
IV = Encrypted_Bytes[0:16]
Ciphertext = Encrypted_Bytes[16:]

         ↓ (DECRYPT)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 5: AES DECRYPTION                                         │
├────────────────────────────────────────────────────────────────┤

Payload_JSON = AES-256-CBC-Decrypt(
  key=Encryption_Key,
  iv=IV,
  ciphertext=Ciphertext
)

         ↓ (PARSE PAYLOAD)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 6: PARSE DECRYPTED PAYLOAD                               │
├────────────────────────────────────────────────────────────────┤

Payload = JSON.parse(Payload_JSON)
Message = Payload["message"]
Received_F1 = Payload["hmac"]

         ↓ (REGENERATE HMAC)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 7: REGENERATE HMAC FOR VERIFICATION (F2)                 │
├────────────────────────────────────────────────────────────────┤

Using K1 from database
F2 = HMAC-SHA256(
  key=User.K1,
  msg=JSON_CANONICAL(Message)
)

         ↓ (VERIFY HMAC)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 8: VERIFY HMAC (Timing-safe comparison)                  │
├────────────────────────────────────────────────────────────────┤

✓ IF F1 == F2:
  - Message integrity confirmed
  - No tampering detected
  
✗ IF F1 != F2:
  - Reject transaction (401)
  - Possible attack detected

         ↓ (VALIDATE TIMESTAMP)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 9: TIMESTAMP VALIDATION (REPLAY ATTACK PREVENTION)       │
├────────────────────────────────────────────────────────────────┤

Last_Timestamp = User.last_transaction_timestamp
Current_Timestamp = Message.timestamp

✓ IF Current > Last:
  - Valid transaction
  
✗ IF Current <= Last:
  - Reject (replay attack detected)
  - Ensure monotonic ordering

         ↓ (EXECUTE TRANSACTION)
         
┌────────────────────────────────────────────────────────────────┐
│ STEP 10: EXECUTE TRANSACTION                                   │
├────────────────────────────────────────────────────────────────┤

1. Deduct from sender: Sender.balance -= amount
2. Add to receiver: Receiver.balance += amount
3. Update timestamp: Sender.last_transaction_timestamp = timestamp
4. Record transaction with encrypted_payload + hmac
5. Return success with transaction_id and new_balance
```

## 🛡️ SECURITY FEATURES BREAKDOWN

### **1. CONFIDENTIALITY (AES-256-CBC)**
```
Transaction Data Encryption:
├─ Plaintext: {sender, receiver, amount, timestamp, HMAC}
├─ Algorithm: AES-256-CBC
├─ Key: Derived from password + timestamp (128 bits of entropy from password)
├─ IV: Random 16 bytes per transaction
├─ Output: Encrypted ciphertext (unreadable without password & timestamp)
└─ Protection: Only sender, receiver, and server can decrypt
```

### **2. INTEGRITY (HMAC-SHA256)**
```
Message Authentication:
├─ Key: K1 (derived from NID + Activation + MAC + Password)
├─ Input: Message {sender, receiver, amount, timestamp}
├─ Output: 64-character hex (HMAC value)
├─ Verification: Timing-safe comparison
└─ Protection: Detects any modification in transit or at rest
```

### **3. AUTHENTICATION (Password Verification)**
```
User Verification:
├─ Storage: SHA256(Password) stored in database (K2_Hash)
├─ Verification: Compare SHA256(Provided_Password) == K2_Hash
├─ Frequency: Required for every transaction
└─ Protection: Confirms user identity before transaction execution
```

### **4. REPLAY ATTACK PREVENTION (Timestamp)**
```
Transaction Ordering:
├─ Each transaction has unique timestamp
├─ Server validates: Current_Timestamp > Last_Timestamp
├─ Prevents: Same transaction being sent multiple times
├─ Ensures: Strict chronological ordering per user
└─ Protection: Impossible to replay old transactions
```

## 📊 ENCRYPTION SECURITY LEVELS

### **Level 1: Transport Security**
```
HTTP POST with:
- encrypted_payload (AES-encrypted)
- hmac_value (computed HMAC)
- timestamp (transaction time)
- password (for verification)
```

### **Level 2: Server-Side Verification**
```
Multiple checks before execution:
1. Session validation (authentication)
2. Password verification (authorization)
3. Payload decryption (confidentiality)
4. HMAC verification (integrity)
5. Timestamp validation (anti-replay)
6. Balance verification
7. Limit checking
```

### **Level 3: Database Storage**
```
Data stored encrypted:
- encrypted_payload (in transactions table)
- hmac_value (in transactions table)
- K1 (user HMAC key)
- K2_Hash (password hash, not reversible)
```
